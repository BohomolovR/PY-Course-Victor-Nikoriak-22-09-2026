# Урок 8. П1. Big O + базові задачі

**Тип:** Практикум (клас). **Передумови:** уроки 4–7 (умови, цикли, функції). **Розв'язує:** нова вісь оцінки рішення — не лише «чи правильна відповідь», а й «скільки роботи воно виконує».

Це перший практикум **алгоритмічної трійки** курсу — три пов'язані практикуми, що разом формують одну навчальну дугу:

```text
              ALGORITHMIC THINKING
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼

       П1            П2          П3
    EVALUATE        CHOOSE     REPRESENT

   complexity      strategy    data structure
       │              │            │
       └──────────────┼────────────┘
                      ▼
             TRADE-OFF THINKING
```

```text
П1 — EVALUATE
"Наскільки дороге моє рішення?"

        ↓

П2 — CHOOSE
"Яку властивість даних
я можу використати?"

        ↓

П3 — REPRESENT
"Чи можу я змінити представлення даних,
щоб отримати кращий алгоритм?"
```

П1 — вхідна точка цієї дуги: тут з'являється саме поняття вартості рішення, яким П2 і П3 користуватимуться далі. **Це не урок про перевірку правильності відповіді** — Big O не перевіряє коректність, два алгоритми можуть давати ідентичний правильний результат.

## RETRIEVE

Коротке пригадування без підглядання: скільки разів виконається тіло циклу `for x in range(n)`, що станеться, якщо один `for`-цикл покласти всередину тіла іншого, яким виразом перевірити належність значення списку.

## CONCEPT — два правильні рішення, різна ціна

Задача: чи є в списку повторювані елементи? Два способи — обидва дають правильну відповідь:

```python
def has_duplicates_v1(data):
    for i in range(len(data)):
        for j in range(i + 1, len(data)):
            if data[i] == data[j]:
                return True
    return False


def has_duplicates_v2(data):
    seen = set()
    for value in data:
        if value in seen:
            return True
        seen.add(value)
    return False
```

Обидва рішення правильні. `v1` для кожного елемента заново переглядає (майже) весь список — вкладений цикл. `v2` дивиться на кожен елемент рівно один раз і використовує `set` для миттєвої перевірки «чи бачили ми це вже». Яке рішення дорожче — і наскільки? Відповідаємо, рахуючи операції, а не покладаючись на відчуття «здається, швидше».

Трьох рівнів достатньо для цього практикуму:

| Позначення | Що означає | Приклад |
|---|---|---|
| `O(1)` | стала кількість дій, не залежить від розміру даних | `data[0]`, `len(data)` |
| `O(n)` | кількість дій росте пропорційно розміру даних | `has_duplicates_v2`, один прохід циклом |
| `O(n²)` | кількість дій росте пропорційно квадрату розміру даних | `has_duplicates_v1`, цикл усередині циклу |

Формальна нотація, історія позначення, `O(log n)`, `O(n log n)`, внутрішня механіка CPython — за межами цього практикуму (частина з них — тема наступного, П2).

## PREDICT → RUN → INVESTIGATE

Список `sample` має 5 елементів. **Прогноз перед запуском:** список у 10 разів більший (50 елементів, без дублікатів — найгірший випадок) — у скільки разів більше операцій зробить кожна версія? Інструментуємо обидві функції лічильником порівнянь і перевіряємо:

```text
v1 (вкладені цикли): n=5 -> 10 порівнянь, n=50 -> 1225 порівнянь (x122.5)
v2 (set):             n=5 -> 5 порівнянь,  n=50 -> 50 порівнянь   (x10.0)
```

`v2` виконує рівно в 10 разів більше операцій при вході в 10 разів більшому — це `O(n)`: пропорційно розміру даних. `v1` виконує приблизно в **100+ разів** більше (`10²`) — це `O(n²)`: подвійний вкладений цикл, ціна росте як квадрат розміру. Прогноз підтверджено реальним підрахунком, а не оцінкою на око.
