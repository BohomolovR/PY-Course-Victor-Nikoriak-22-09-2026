# Урок 6. Словники, for, comprehensions

**Передумови:** уроки 4–5 (умови, `while`, списки/кортежі/множини). **Розв'язує:** перетворення — як перебирати, підраховувати й групувати дані, і як записувати цикл компактніше.

## RETRIEVE

Коротке пригадування без підглядання: чим `tuple` відрізняється від `list` за призначенням (не за синтаксисом), чому `set` прибирає дублікати, чому генерація унікальних позицій бомб на дошці — задача для `while`, а не для `for`.

## CONCEPT

### `dict` — доступ за ключем, а не за позицією

Список шукає елемент за **позицією** (`fruits[0]`). Словник шукає за **ключем** — будь-яким незмінним значенням:

```python
student = {"name": "Олена", "age": 20, "group": "КН-21"}
student["name"]            # доступ за ключем
student["email"]           # KeyError — ключа немає
student.get("email")       # None — безпечно, без падіння
student.get("email", "—")  # "—" — своє запасне значення
```

### Три способи ітерувати словник

```python
for key in d:          # тільки ключі
for val in d.values():  # тільки значення
for k, v in d.items():  # пари (ключ, значення)
```

**Типова пастка:** `for k, v in d` (без `.items()`) намагається розпакувати сам **ключ** (рядок) у дві змінні — і падає з `ValueError`, якщо довжина ключа не дорівнює точно 2. Причина: `for key in d` віддає рядки на кшталт `"Alice"`, а розпакувати п'ятисимвольний рядок у дві змінні неможливо.

### `.setdefault()` — читання з автоматичним створенням

`d.setdefault(key, default)`: ключ є — просто повертає значення; ключа нема — створює `d[key] = default` і повертає його. Найкорисніше для накопичення в списки:

```python
teams = {}
teams.setdefault("Backend", []).append("Олег")
teams.setdefault("Backend", []).append("Ірина")   # ключ вже є — список не перестворюється
# {'Backend': ['Олег', 'Ірина']}
```

### Патерн Counting — підрахунок частоти

```python
counts = {}
for char in "banana":
    counts[char] = counts.get(char, 0) + 1
# {'b': 1, 'a': 3, 'n': 2}
```

`d.get(key, 0) + 1` — стандартний прийом "прочитати поточне значення або 0, якщо ще не було".

### Патерн Grouping — розширення Counting

Замість того щоб рахувати, збираємо самі значення у списки за ключем:

```python
by_parity = {}
for n in numbers:
    key = "парні" if n % 2 == 0 else "непарні"
    by_parity.setdefault(key, []).append(n)
```

### List comprehension — той самий цикл, компактніший запис

Спочатку звичайним циклом, потім та сама ідея одним рядком:

```python
# Цикл
even_squares = []
for x in range(1, 11):
    if x % 2 == 0:
        even_squares.append(x ** 2)

# Comprehension — той самий результат
even_squares = [x ** 2 for x in range(1, 11) if x % 2 == 0]
```

```
[ що_зберегти   for елемент in колекція   if умова ]
  ↑ Transform       ↑ Iterate               ↑ Filter
```

**Правило:** comprehension будує **новий список**. Якщо мета — виконати дію (`print`, запис у файл) без побудови колекції — використовуйте звичайний `for`.

Та сама логіка працює і для словників (`{w: len(w) for w in words}`) — спочатку зрозумілий цикл, потім компактний запис, ніколи навпаки.

## CREATE — Minesweeper крок за кроком

Наскрізний приклад уроку — гра «Сапер» на дошці 8×8 із 10 бомбами, побудована **без жодної функції** (функції — тема Уроку 7): фрагмент коду → пояснення → запуск → наступне розширення.

1. **Позиції бомб** — `set` кортежів `(row, col)` + `while len(bombs) < 10` (множина сама відкидає дублікати; `while`, бо наперед невідомо, скільки випадкових спроб знадобиться).
2. **Прихована дошка** — спочатку подвійним циклом, потім nested list comprehension `[["." for col in range(SIZE)] for row in range(SIZE)]` — обидва варіанти дають однаковий результат, comprehension компактніший. (Пастка, якої тут свідомо немає: `[["."] * SIZE] * SIZE` повторює **один і той самий** внутрішній список 8 разів, а не створює 8 незалежних рядків.)
3. **Друк дошки** — заголовок з номерами колонок + рядок за рядком.
4. **Зчитування ходу** — `while True`, поки гравець не введе два коректних числа в межах дошки; перевіряється окремо, з підміненим `input()`, без реальної клавіатури. (На зафіксованому `seed=42` цей самий хід виявляється потім бомбою — навмисний "гачок" до наступного кроку.)
5. **Підрахунок бомб навколо клітинки** — подвійний цикл по зсувах `(-1, 0, 1) × (-1, 0, 1)`, спочатку на ізольованому тестовому прикладі.
6. **Одна ітерація ходу** — з'єднуємо кроки 1, 2, 4 і 5: три гілки (вже відкрито / бомба / підрахунок і відкриття), застосовані до реального стану дошки. Хід із кроку 4 виявляється саме тим бомбовим ходом; для продовження береться свіжа безпечна клітинка.
7. **`while ... else` і повний цикл** — окрема міні-демонстрація `while...else` (навіщо `else`, коли він спрацьовує, а коли — ні через `break`), потім складання кроків 1–6 у повний ігровий цикл з лічильником `opened`; перевіряється "наосліп" (підмінений `input()`, фіксований `random.seed`) на заготовленому списку ходів.
8. **Показ бомб наприкінці** — застосовується напряму до реального стану дошки з кроку 6, потім дописується в кінець зібраного скрипту з кроку 7.
9. **Звірка з Уроком 7** — щойно написаний скрипт запускається поруч із реальним файлом [`minesweeper_before_refactor.py`](https://github.com/NikoriakViktot/PY-Course-Victor-Nikoriak-22-09-2026/blob/main/module_1/lessons/lesson_07_functions/resources/minesweeper_before_refactor.py) під тим самим `seed` і тим самим списком ходів — `assert` на побайтово однаковий вивід доводить, що це справді та сама гра, а не просто показ готового файлу.

Гру перевірено "наосліп" (підмінений `input()`, фіксований `random.seed`): сценарій програшу (перший же хід — бомба, крок 6) і сценарій повної перемоги (усі 54 безпечні клітинки відкриті послідовно, повний зібраний скрипт) — обидва проходять коректно.

## CREATE — другий наскрізний приклад: аналітика ресторану

Другий, повністю незалежний наскрізний приклад — той самий цикл мислення (дані → накопичення в `dict` → результат), але на бізнес-даних, а не на грі: 244 реальні чеки ресторану (`seaborn.load_dataset("tips")`), уже знайомі з Уроку 5 як `orders: list[Order]`, де `Order` — `NamedTuple` з полями `total_bill, tip, sex, smoker, day, time, size`.

**Повторення з Уроку 5 (коротко):** `orders` перебудовується тим самим list comprehension'ом, що й у попередньому уроці, — щоб продовжити з тієї самої точки, без повторного пояснення `NamedTuple`.

**Counting → Aggregation → Grouping, один патерн за раз, кожен вручну перед comprehension-версією:**

1. Наївний `d[key] = d[key] + 1` падає з `KeyError` — демонструється навмисно (в `try/except`, щоб не зупиняти виконання ноутбука), тоді виправляється через `d.get(key, 0) + value`.
2. Повний прохід по всіх чеках будує `revenue_by_day`, `orders_by_day`, `guests_by_day` — з `assert`, що сума по днях збігається із загальним доходом і кількістю чеків.
3. **Leader algorithm**: ручний пошук «поточного чемпіона» проти `max(d, key=d.get)` — `assert`, що обидва варіанти дають один і той самий день. Той самий патерн повторюється без жодної зміни логіки для `order.time` замість `order.day`.
4. **`set`**: ручний `set.add()` проти set comprehension для унікальних днів/часу/розмірів столу — з `assert` на рівність.
5. **Grouping**: `dict.setdefault(key, []).append(order)` — зберігаємо самі об'єкти `Order`, не лише лічильник; `assert`, що сума розмірів груп дорівнює кількості чеків.
6. **`defaultdict`**: усі три патерни (Counting/Aggregation/Grouping) переписані через `defaultdict(int)`/`defaultdict(float)`/`defaultdict(list)` — з `assert`-порівнянням проти щойно порахованих `.get()`/`.setdefault()`-варіантів, щоб довести, що це справді той самий результат, а не просто інший синтаксис.
7. **`Counter`**: третій спосіб рахувати, коли потрібна лише кількість — `Counter(order.day for order in orders)` проти `.get()`-підрахунку, з `assert` на рівність.
8. **List і dict comprehensions на реальних даних**: фільтр (`total_bill > 40`), трансформація (tip% для кожного чека), фільтр+трансформація (чеки на вечерю), і `top10` через `sorted()` + зріз — усе спочатку зрозумілим циклом, де це доречно, потім comprehension, завжди з `assert`, що результати узгоджені (наприклад, кількість «великих» + «малих» чеків дорівнює загальній кількості).
9. **Фінальний звіт для власника**: один блок, що зводить усі вже пораховані агрегати (найкращі дні, обід vs вечеря, розміри столів, топ-3 чеки) — з `assert`, що обід + вечеря дають загальний дохід і що сума по днях узгоджена.

Візуалізація (`matplotlib`) — поза межами цього уроку, лише одна згадка без реального коду.
